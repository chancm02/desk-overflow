## Domain and DNS runbook — no purchase
Candidate branding: deskoverflow.com, deskoverflow.ai or getdeskoverflow.com. Availability, trademark suitability and price are UNVERIFIED. Owner chooses and approves registrar purchase separately; enable MFA, privacy if available, auto-renew only with consent, and business-controlled ownership/recovery. No CNAME file is committed because that can alter publishing behavior.
If retaining GitHub Pages: verify domain ownership with GitHub-provided TXT; obtain current apex A/AAAA targets and www CNAME from GitHub Settings > Pages official instructions. Do not guess IP addresses. Set www CNAME to the exact provided hosting target and choose one canonical hostname. If moving to HighLevel hosting, use its generated website domain records instead; never set competing web records. Export DNS before edits, preserve MX, choose short TTL such as 300 during planned change, verify resolution + valid HTTPS + apex/www redirects before ads. No wildcard DNS required.
Email: use owner-selected business mailbox. Add HighLevel-generated SPF/DKIM and sending-domain records on a dedicated subdomain where recommended; maintain ONE SPF record per hostname and preserve existing senders. Set DMARC initially monitoring only after mailbox approval; review reports before enforcement. MX changes require mailbox migration approval. Never copy sample DKIM keys from documentation.
After approved cutover: update og:url, canonical metadata, privacy/contact sender and all absolute links; test certificates, redirects, email authentication, form persistence and notifications. Rollback uses saved DNS and host settings; allow propagation. Domain records and sender details remain pending authenticated host/registrar access.
