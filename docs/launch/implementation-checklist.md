# HighLevel implementation session checklist

Everything here is prepared for manual entry in the native account. JSON files are specifications and fixtures, not HighLevel API payloads or importable Snapshots. All external-send, charging, AI dialing and production-routing actions stay off until their specific approvals. Use [customer-agreement-packet.md](customer-agreement-packet.md) as editable source; no preexisting drafts are needed.

## Before authenticated access
- Preparation checks and tests: `python tools/check_preparation.py`, `python -m unittest discover -s tests -v`, `node --check assets/site.js`, `git diff --check`.
- Native asset sources are under assets/: field catalog, onboarding form, FAQ worksheet, test customer, acceptance results, budget inputs and release checklist. No real contact import is needed.
- Copy working business values, customer records, test results, platform IDs and rates into ignored private/ or the authorized CRM. Never enter them into committed examples.
- [Message templates](message-templates.md), [DNS change sheet](dns-change-sheet.md), [privacy source draft](privacy-source-draft.md), [legal review brief](legal-review-brief.md), agent prompt in highlevel-build.md and test plan are ready for the account build.

## Account setup session
1. Owner authorizes plan, 30/90-day budget and any number/wallet charges; owner creates account and completes platform terms/MFA/recovery. Keep upgrades, SaaS automation and paid add-ons disabled. Confirm three Starter locations and Snapshot feature availability before committing to that plan.
2. Create separate Sales, Template TEST and Customer TEST locations if the plan permits. Configure business identity, America/Chicago default for Desk Overflow, user access and verified sending identity. Customer timezone must be its own value. No real lead data in Template.
3. Create the custom fields using field-catalog.json, mapping supported native equivalents and recording actual IDs privately. Create the pipeline in highlevel-build.md; exact stage names must match workflow filters.
4. Build inquiry and onboarding forms; set required response permission, privacy version, spam controls, labels and clear success/error states. Add no marketing consent. Bind official embed only after field persistence and native receipts are tested. Preserve original site layout.
5. Create draft templates from the agreement packet and approve/rebind native merge fields. Retain DRAFT labels until legal/owner review. Do not send documents with any bracketed field. Set contract invoice sending, direct payment and auto-pay OFF. Confirm primary signer behavior. Complete gateway verification through owner-led secure screens; make Test mode visually explicit.
6. Create $500 one-time and $499 recurring products. Keep live schedules off. Build one billing path only: draft setup invoice after approved signature; recurring schedule starts at accepted activation date. Do not create a second subscription on top of recurring invoices. Owner approves actual tax treatment, disclosure and recurring mandate.
7. Build inbound-only agent with approved FAQs and calendar actions. Bind authorized test numbers only; verify the selected number is not a real default business line. Disable every missed-call text-back, SMS reminder, promotional call, automated callback and trial-default campaign that could send to real contacts. A human transfer during an inbound call must use only the approved target; it may still incur outbound leg costs.
8. Build DO-01 through DO-10 as drafts. Verify exact triggers, field mappings, duplicate guards and fallback for unsupported actions. Test notifications only to authorized test recipients. Keep all production sends behind reviewed conditions and no live-number enrollment.
9. Open AI Usage Limits, enable a finite approved budget and explicitly select **Block AI at the limit**, if it applies to the chosen Voice AI product/plan. Do not leave default **Keep AI running, just notify**. Confirm account overrides, included-plan exclusions and calendar-month resets. This is not a cap on all telephony. Measure phone and transfer charges separately; test low-wallet and blocked-AI routing. If Voice AI is not covered, native caps cannot be relied on and exposure requires another verified platform/carrier control before activation.
10. Use acceptance-results.blank.json to record all 20 account tests. Confirm gateway sandbox, replay protection, routing loop prevention, calendar race behavior, access isolation, required consent and actual fallback. Never dial the reserved dummy phone number in test-customer.json.
11. Export a native Snapshot from the isolated tested source. Load into test destination, reconnect destination-specific calendar/gateway/sender/number and inspect all references. Re-run critical tests. Snapshot import is not activation and should not contain live records or credentials.
12. Prepare final reviewed site integration and privacy source. Stop before merge/publish, customer document sending, paid number purchases, real charges or live forwarding until the corresponding approval is recorded.

## Private deployment record
Record date, operator, account/location IDs, asset/version IDs, template approval record, authorized test numbers/recipients, gateway mode, calendar ownership, selected AI plan and verified rates, per-customer and agency spend limits, expected billing periods, duplicate test results, emergency/fallback scripts, carrier rollback procedure, incident contacts, all 20 test results and final approvals. Use native CRM links or restricted private records for evidence.

## Operational cadence
Daily in first week: compare call logs to outcomes, inspect failed executions and delivery, resolve overdue callback tasks, check usage/wallet and calendar sync. Weekly: report received calls/leads/bookings, unresolved issues, actual costs and FAQ changes. Monthly: reconcile invoice/transaction amounts and renewal authorization, review access and retention/export tasks. No manual report should claim unavailable calls or revenue recovered. No customer-impacting automated retry occurs without verifying the prior operation did not complete.

## Data and security procedure
Use unique MFA logins; authorized users only in the intended location. Send protected record links in alerts. A deletion/export request requires independent requester verification and a recorded scope; check preservation duties, disconnect unnecessary integrations and document native/backup limitations. An incident uses the fallback procedure in onboarding-acceptance.md, restricts affected access, records confirmed facts and gets owner/counsel review for external notices. Secrets stay in native authorized connections or a credential manager.
